# 模型与工作模式界面记录

基础界面核对日期：2026-11-03；命令与上下文更新：2026-11-05。以下参考均为官方文档或项目官方仓库。本项目采用自己的页面实现，以 Pi 1.4.0 为运行时。

| 参考 | 已核对的设计 | 本项目应用 |
| --- | --- | --- |
| [Cursor Plan Mode](https://cursor.com/docs/agent/plan-mode) | 输入区模式下拉、Shift+Tab 切换、先调研出计划再执行 | 聊天框下方 Agent / Plan / Ask，Plan 不自动转执行 |
| [Claude Code 权限模式](https://code.claude.com/docs/en/permission-modes) | Plan 先研究与提出变更方案，再进入执行流程 | 模式需要约束实际行为。本项目采用更保守的内置读取/搜索工具白名单，Plan 不开放 shell 命令 |
| [Claude Code 命令](https://code.claude.com/docs/en/commands) | `/context` 查看上下文占用，`/compact` 总结较早对话释放空间；命令按工作目的组织 | 输入 `/` 搜索命令；上下文和压缩同时保留在输入框下方，直接查看用量与状态 |
| [CC Switch FetchedModelPicker](https://github.com/farion1231/cc-switch/blob/main/src/components/providers/forms/FetchedModelPicker.tsx) | 搜索模型、复选框选择、草稿集合、确认后批量应用，保留配置中已有 ID | 服务表单内可搜索的下拉多选，筛选不丢失选择；确认时保留已有参数和手填 ID |
| [CC Switch PiProviderForm](https://github.com/farion1231/cc-switch/blob/main/src/components/providers/forms/PiProviderForm.tsx) | 模型获取与服务配置配合使用，连接配置改变后使旧获取结果失效 | 改协议、URL、Key 后清除旧发现列表；获取与实际推理测试分开 |
| [Codex App 功能入口](https://developers.openai.com/codex/app/features) | 查询了官方功能页作为整体工作流参考 | 未复刻 Codex 的完整桌面功能，也不据此宣称能力对齐 |

页面职责：聊天框负责当次工作选择；设置负责连接、认证和可用模型管理。主流程保留项目、工作模式、模型与发送。模型与当前推理强度合并为一个入口，展开后搜索模型、选择模型支持的强度；主界面不再单列“思考：关闭”。

命令和上下文也围绕输入框组织。输入 `/` 时显示命令菜单，平时仅保留一个低存在感的“命令”入口；`/model`、`/mode`、`/context`、`/compact`、`/changes`、`/settings` 和 `/help` 是 Web 操作。菜单使用操作、技能、模板分类，已加载的扩展独立标注；“技能”是筛选分类，不再将 `/skills` 浏览入口与具体技能并列。分类可在已选择项目和模型后初始化 Pi 会话、发现资源，不发送模型请求；选择具体技能或模板先补全到输入框，用户可以追加任务再发送。旧 `/skills` 输入仍可跳转到技能分类，但不占用菜单项目。模型可依据运行时提供的技能说明按需读取完整指令，沿用 Pi 的渐进加载机制。操作显示明确的中文标题，以区分 `/model` 模型选择和 `/mode` 工作模式；完整输入只显示精确匹配，同名项目去重。鼠标点击打开面板时阻止该点击继续冒泡，避免刚打开就被外部点击处理器关闭，键盘与鼠标路径分别验收。扩展命令和技能不会在 Plan / Ask 中绕过只读限制，未知命令保留在输入框并给出提示。上下文按钮显示实际运行时估算；只有有可靠 token 估算时才显示百分比，压缩后明确显示待下一次模型回复更新，避免把历史数值冒充当前占用。压缩按钮与上下文详情位于输入框下方，执行中锁定发送、模型设置和其他会改变执行状态的操作，允许取消手动压缩。

代码变更通过会话右上角的入口打开。宽屏下，文件列表与差异预览位于对话右侧，分别滚动；收起后恢复完整聊天宽度。窗口较窄时使用右侧抽屉，支持 Escape、遮罩关闭和键盘焦点约束。运行中可以查看和刷新；同一会话的快照与刷新保留选中文件和差异滚动位置，文件消失或切换会话时清除旧内容，过期请求不能覆盖新选择。审阅范围仍是当前 Git 工作区与暂存区，保留任务前已有修改的标记。

发送、停止与继续统一在聊天输入框右下角，按运行状态显示一个主操作。运行时使用方形停止图标，中断后在空输入框显示“继续”；输入新内容时恢复发送，Enter 提交、Shift+Enter 换行。停止沿用 Pi 的中断机制，等待模型、工具和验证结束后才开放继续。普通会话在原上下文追加明确的继续请求；规划任务沿用显式恢复入口，从当前工作区的只读检查开始。继续之前应用暂存的模型与强度，重复点击、发送竞争和失败不会清除草稿。

回答在流式输出期间使用与完成后相同的 Marked 解析和 DOMPurify 清洗，每 32ms 合并一批片段。已完成的 Markdown 块保留原节点，生成中的代码块保留滚动位置和复制按钮；未闭合的代码围栏由解析器按当前内容显示。最终消息立即渲染权威正文，重连快照与切换会话取消旧渲染队列；向上阅读历史时不强制追到底部。模型输出的 HTML、图片与链接仍按原有规则处理。

MCP 放在独立设置分类，列表只显示配置范围、传输、启用状态、最近测试与常用操作。添加/编辑进入单服务表单，OAuth 和 JSON 导入折叠；已有凭据只显示已配置，不回填。命令参数逐行输入，避免 Windows 路径的空格被拆分。全局与项目同名配置并列标明覆盖关系，项目局部覆盖不复制凭据。配置事件不会重建正在编辑的表单，失败时保留草稿。最近测试与实时连接状态明确区分；详见 [MCP 管理](mcp-management.md)。

推理能力以 Pi 1.4.0 的 `getSupportedThinkingLevels` 和 `clampThinkingLevel` 为准。只有显式映射的 `xhigh/max` 才出现；被 `null` 禁用的档位不出现。没有模型、未启用推理、固定档位和可调档位分别说明，不显示一个打不开的假开关。强度选择会保存到 Pi 的每模型偏好；历史对话仍以自己的已保存强度为准。切换文本模型不会覆盖其他模型的偏好。

第三方服务保留列表中明确返回的能力信息；仅有名称时不推测能力。模型编辑中直接展示推理能力与档位。按完整 ID、协议匹配 Pi 目录提供可选模板，注明来源，由用户选择；相同模型在不同服务上可能支持不同档位。原有配置中保存的 `reasoning: false` 保持原意，可通过聊天模型菜单的“设置推理能力”直接打开对应模型修改。

配置保存期间锁定模型、强度、模式和发送，显示保存状态；失败时显示原因并保留草稿。当前会话的模型能力与强度以服务器快照为准。模型菜单支持搜索、键盘、Escape 关闭与焦点返回；窄屏使用同一入口并限制面板在视口内。

模式由服务器保存，不能从提示词或模型输出提高权限。Pi 仍负责运行循环、模型调用、工具、会话、资源与信任。只读约束作用于模型驱动的工具调用和 Web 命令分派；可信扩展自身仍拥有启动用户的操作系统权限。

验收使用独立 Pi home、临时项目和本地模拟模型，不向用户真实模型发起测试请求。自动检查包含只读工具执行、被阻止的写入/命令、验证跳过、Agent 验证失败、模式恢复与运行锁；浏览器验收包含批量选择、聊天模型切换、Plan 对话、刷新恢复及 390px 布局。

技能管理收在设置的“技能”分类，命令菜单的技能分类提供轻量管理链接；管理入口不和具体技能并列。列表按范围筛选和搜索，展示来源、实际生效状态、手动调用标记和诊断。内容以纯文本预览，启停写回 Pi 原生资源路径或资源包过滤，额外本机目录使用 Pi 的 skills 设置保存。移除目录引用保留本机文件，项目修改需要信任。浏览只调用 Pi 的包路径解析与技能解析，不加载扩展，不自动安装资源。保存后与模型、MCP 和会话操作互斥，重新加载受影响的空闲会话并重施工作模式策略。

输入区选择器使用统一高度与行高，文字、推理强度标记和 SVG 下拉箭头在同一条水平中线；输入框上下内距一致。执行过程和工具详情的展开符号使用几何箭头，避免字体字符的基线偏移。

历史会话围绕项目收纳。项目行使用文件夹图标与独立展开箭头；会话标题、更新时间分行，常用操作收进悬停或键盘聚焦时出现的省略菜单，支持右键。会话顶部保留轻量菜单，重命名不再占据标题旁的显著按钮。置顶、归档、回收站和恢复均直接追加 Pi 会话记录；归档与回收站保留原文，恢复后再继续对话。活动列表保留尚无会话的项目，归档与回收站只显示对应记录。历史刷新使用请求序号，旧响应不能覆盖更新后的列表。

消息分支沿用 Pi 1.4.0 的 `SessionManager.createBranchedSession()`，不复制或重建模型循环。用户纯文本消息的分支回到该消息之前的上下文，将选中的消息放入草稿供修改；完整回答的分支保留该回答，从空草稿继续。图片消息保留已有附件后继续。分支创建不发送模型请求，原会话与草稿保留，分支标题旁可以返回原会话。新分支重置任务和验证证据，不能把原会话的完成状态当作新任务已验证。服务端只接受当前分支的有效消息点，拒绝工具调用中间态、运行中或压缩中分叉；会话文件在打开前检查真实路径及头部，路径别名复用同一运行时。
