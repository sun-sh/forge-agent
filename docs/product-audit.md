# Forge Agent 产品与工程审查

审查范围：0.2.0 活动源码、测试、双语 README、评测和发布脚本。Pi Coding Agent / Pi AI 固定为 1.4.0。这里只评价实现与证据，不把 fixture 或 CI 当作真实模型编码能力。

## 判断

Forge 已具备本机 Web coding agent 的主要产品链路：项目与会话、第三方模型、流式对话、工具执行、验证、停止恢复、MCP、Skills、作用域记忆、子任务、变更审阅和后台运行。它适合本机开发与早期公开反馈。可展示的 Agent 开发能力在任务状态、完成门禁、权限策略、执行所有权、预算、持久化与恢复设计；Pi 负责成熟的模型/工具循环，不另造运行时。

本轮补上了上次提出的七类实现缺口。真实仓库编码质量和长期可靠性仍需要实测，不能由功能数量推断与成熟产品效果等价。

| 维度 | 已实现 | 证据或限制 |
| --- | --- | --- |
| 完成与失败 | 自适应和显式规划执行、有限修复、原始验证输出、预算、任务恢复 | `src/task/`、`src/verification/`；模型自审仍不是独立正确性证明。 |
| 变更恢复 | 工作文件检查点、按文件 diff/撤销、脏基线保留、HEAD/index 与后续修改检查 | `checkpoints.ts`；逐文件日志，没有跨文件原子事务、全局快照回收或备份保证。 |
| 后台运行 | detached 本机网关、持久化 FIFO、固定设置、实例认证启停、明确重新排队 | `queue.ts`、`service.ts`；单 home 单 owner、单队列执行，不是 OS 开机服务或分布式调度。 |
| 子 Agent | 独立 Pi 上下文、受限只读角色、worktree worker、选择应用和清理 | `subagents.ts`、`worktrees.ts`；无 shell、自动三方合并、独立子模型或面板续聊。 |

| 记忆 | 全局/项目/会话、待审阅候选、来源、去重、显式替换和版本冲突 | `memory.ts`；候选未经接受不注入，无向量检索和质量增益结论。 |

## 值得展示的工程取舍

- **完成由证据控制**：配置验证失败不能作为成功结束；自动继续不重置修复次数，规划流程还要求有效审阅和新鲜 Git 证据。
- **副作用有所有权**：同一真实项目的 Agent、终端、Trust 变更、撤销与 proposal 应用共享执行租约。服务关闭先停止准入，再等待打开会话、活跃执行和清理。
- **持久化先于可见成功**：队列落盘后准入，公开快照来自已提交状态，避免界面显示完成而重启后还看到运行中。损坏队列保留原文件并拒绝静默重建。
- **恢复不重放工具**：执行进程退出后标记中断；用户明确继续或重排时先读当前项目状态。未封存或写入中断的检查点不会自动恢复。
- **原有工作有基线**：检查点记录执行前脏内容，撤销不 reset Git；worker 在隔离目录提出补丁，主项目有后续改动时拒绝覆盖。
- **会话归属有边界**：普通 fork 不继承原会话的子任务、检查点或待审阅记忆所有权。UI 的晚到响应和旧按钮也检查当前会话。
- **复用覆盖运行时**：Pi 负责 agent loop、模型、认证、会话树、压缩、内置工具、MCP、Skills、扩展和发现。Forge 控制宿主策略和产品流程，不复制第二套协议或模型循环。

## 本轮修正的失效路径

会话启动期间的加载纳入 shutdown 等待，避免关闭后晚到的 Agent 重新挂回网关。准备阶段失败会释放项目占用并恢复空闲；收尾失败保存失败状态并释放租约。Provider 更新无法重绑定时退休真实 Agent，历史置为只读；删除提交后目录刷新失败不会复活已删除凭据。空闲子会话 abort 或重复 dispose 的尽力清理错误不会篡改已完成结果。

可写子任务还拒绝 Pi 会展开的特殊路径表示，以及父目录链接、硬链接、敏感路径和 Windows 路径别名，确保检查目标与实际写入语义一致。这些是应用控制，不是 OS 沙箱；可信扩展、普通 Agent 工具和验证命令仍拥有启动者权限。

## 仍应优先取得的证据

1. **真实模型仓库效果**：用固定提交和独立 oracle，对 bug 修复、功能、重构、已有脏改动与中断恢复做 direct/planned 重复对照。保留错误完成、越界修改、token、延迟、成本和失败样例。基础设施通过不代表任务已经测过。
2. **外部服务兼容矩阵**：对实际使用的 Provider 和 MCP 分别记录模型、协议、流式工具、错误/限流、代理、OAuth 与重连结果。fixture 无法替代服务验收。
3. **长期运行和容量**：需要长时间队列/取消/重启压力测试、检查点全局容量治理、孤立 worktree 清理和更完整的终端运行 ID/取消协议。当前终端仍是有界 HTTP 请求。
4. **上下文与记忆收益**：候选审阅解决写入控制，尚未证明召回或结果改善。先设计带/不带记忆及不同上下文预算的对照，再决定向量检索和自动经验管理。
5. **可维护性**：Web gateway 与主 UI 偏集中。应在不改变协议和行为的前提下拆分会话、设置与任务路由，避免为了 UI 框架重写而丢失回归边界。

## README 与展示建议

双语首页按照产品用途、启动、能力、模式、职责、验证、边界和安全组织。测试数量、验收日期和 CI 成绩留在检查结果与 Actions，不放产品介绍。源码和设计文档分别指向本项目实现；公开归因 Pi 完整 runtime，避免把复用描述成从零实现，也避免把有实质控制层的项目描述成换皮。

面向 Agent 开发岗，适合演示三个可复现过程：修改失败后如何被验证门禁拦下；中断/重启后如何重新检查而不重放副作用；worktree proposal 如何审阅应用并保留用户已有脏改动。配合固定仓库评测报告，比堆功能名称更能说明设计能力。
