# Forge Agent 产品审计 · 2026-11-04

当前定位：使用 Pi 1.4.0 运行时的本机 Web coding agent。基础工作流已经能运行，Web 产品仍处在早期阶段。模型能对话、界面能打开、测试通过，都不足以证明已经达到 Codex 或 Claude Code 的整体水平。

## 本轮已经处理

- 聊天框工具栏：项目、工作模式、当前模型与推理强度集中放在输入框下方；设置移除重复的默认模型选择流程，保留服务管理与可用模型目录。
- 模型批量选择：服务获取列表后使用搜索与复选框下拉，支持当前筛选结果全选/清空及确认批量应用；保留手填模型 ID、已有能力参数和当前会话模型。已选模型折叠展示，窄屏打开多选会自动滚入可见区域。
- 工作模式：Agent / Plan / Ask，由 Pi 扩展限制真实工具调用；Plan 与 Ask 仅允许内置读取/搜索，禁止写入、终端命令、MCP/扩展工具、斜杠命令分派和项目验证。切回 Agent 恢复工具与原有验证约束。模式和本轮运行模式随 Pi 会话保存，运行中禁止切换，历史恢复不自动提高执行权限。
- 设计依据与适配说明见 [界面设计记录](ui-design-notes.md)。

- 会话恢复：没有可用模型也可以只读查看历史；切换到可用模型后继续。保留思考、工具调用和结果、上下文压缩与分支摘要。并发打开同一会话复用一个运行时。
- 可靠性：SSE 使用事件游标、去重、重连和当前快照恢复；限制事件缓存和驻留会话数量；初始化、模型切换、信任变更和 prompt 不再互相穿插修改。
- 交互生命周期：确认必须是真正的布尔值；选项必须属于给定列表；超时、停止、关闭服务都会清理等待中的交互。过期确认不会继续执行。
- 信任：撤销信任会卸载运行时及其项目资源；加载资源、执行 prompt 和等待交互时拒绝变更信任；服务关闭后不能继续附加新运行时。
- 完成状态：区分模型报错、停止、验证失败与正常完成；没有配置自动验证时明确显示。报告分别保留检查名称和执行命令；长输出通过完整日志恢复，避免截掉错误尾部。超时及命令启动失败保留原因、原始输出和日志路径，按同一有限预算反馈模型修复；主动停止只保留中断证据，禁止继续检查或修复。再次验证立即清空旧的成功报告。修复 Windows cmd.exe 对带引号命令的二次转义。
- 页面：设置拆分为服务、模型、MCP、项目、关于；按服务筛选、搜索和分批展示可用模型；当前模型统一在聊天框下方切换。增加项目历史搜索、移动端侧栏和命名弹窗。
- 输出：使用 marked 与 DOMPurify 渲染 Markdown，支持代码复制、diff、表格、折叠思考和工具详情。原始 HTML 作为源码显示，防止借用应用样式伪装界面。
- 本机连接：forge-agent web 默认自动打开浏览器并完成已有 token 鉴权流程，终端只显示普通本地地址；用户无需复制或输入凭证。访问凭证保存在 FORGE_AGENT_HOME/web/access-token，重启不再随机更换，浏览器保留 HttpOnly、SameSite=Strict Cookie。未连接标签页会在同一浏览器收到授权后自动恢复，弹窗不再要求粘贴链接。保留草稿和会话指针，不自动重发任务。公开首页不会自动授予 API 权限，Host、Origin、跨站请求检查与 Pi 项目信任保持不变。--no-open 只供自行管理浏览器的工具使用。
- 可重复检查：锁定依赖和 lockfile；补充真实 Chromium 验收脚本，使用临时项目、独立 Pi home、独立浏览器资料和本地模拟模型。
- 第三方模型：设置 → 服务可添加和编辑服务名称、Base URL、协议与 API Key，支持 Chat Completions、Responses、Anthropic Messages。可获取列表后下拉批量勾选或手动输入模型 ID；支持本机免 Key、模型能力及长度参数。实际调用测试经过 Pi 并要求返回文本，与获取列表分开。保存后在聊天框下方选择，不改变当前会话模型。配置仍使用 Pi models.json，Key 通过 Pi 认证 API 保存、不回显；保留其他服务、注释及高级参数，拒绝损坏配置、并发陈旧编辑和运行任务期间的连接变更。更换目标地址需新 Key 或明确免 Key，获取及测试不跟随重定向发送凭据。

## 仍然欠缺的产品能力

本轮已经补齐的核心 Agent 工程能力：

- Web SDK 路径装配 Pi 的 MCP、codemode 和 deferred tool-search 内置扩展，并沿用 Pi 的替换、禁用和项目可信边界。
- MCP Web 管理提供全局/项目配置、JSON 导入、stdio/HTTP 参数、凭据脱敏编辑、启停、删除、真实连接测试与工具列表；支持浏览器 OAuth 登录、取消与退出、逐工具及通配规则、每会话连接状态与空闲重连。配置保存后重载受影响的空闲 Pi 会话；授权完成后更新空闲会话，运行中的会话在本轮结束后更新。Plan / Ask 重载后仍限制真实调用。设计与局限见 [MCP 管理](mcp-management.md)。
- “计划并执行”具备 `Inspect → Plan → Implement → Verify → Review → Complete` 持久阶段、有限修复次数、停止与中断后明确继续。
- 验证结果绑定任务/run ID，原始命令输出保留在证据文件和 Pi 会话分支中。
- 页面提供阶段进度、验证输出、结构化审阅、Git 文件状态、按文件差异和草稿持久化。

## 发布判断

可作为 `0.1.0` 早期版本收集反馈。回归测试和本地浏览器验收证明了受测链路可运行，不能代替真实模型质量评测或外部服务兼容验收。在上述 P1 完成前，不应标注为完整产品或宣称与领先 coding agent 能力对齐。每次发布应重新运行下列检查，以当次输出和 CI 记录为准。

## 验证与边界

- `npm run check`：类型、活动测试、构建和 CLI/bin 入口检查。
- `npm run test:web`：真实 Chromium 页面验收，覆盖 MCP 添加/测试/编辑/禁用/项目覆盖、逐工具配置、OAuth 登录/退出/取消与草稿保留、会话连接状态与重连、凭据不回显、无手动链接输入、HttpOnly Cookie、服务重启后的会话与草稿恢复且不重发任务，以及设置分类、模型下拉、文件夹、Pi prompt、流式回答、自动验证、Markdown diff、历史与 390px 布局。
- MCP 集成使用真实本地 MCP fixture，覆盖直接调用、延迟发现、codemode、禁用/替换、项目可信边界、配置后会话重载、只读模式与关闭后子进程回收。
- `npm run eval:smoke` 使用已知解答检查任务链路；`npm run eval:agent` 才会使用配置的真实模型。原始结果写入 `.forge-agent/evals`，不把模拟任务通过率当作模型编码成功率。
- 浏览器验收用的是本地模拟 OpenAI-compatible 服务，验证 Pi 与 Web 的接入链路；它不代表外部 Provider 的真实认证、兼容性或模型编码能力已经通过。
- 项目信任控制资源加载与验证执行，进程仍使用启动者的操作系统权限。它不构成 OS 沙箱。

推荐顺序：真实任务评测与服务兼容验收 → 会话与输入体验 → 桌面交付。继续沿用 Pi 的运行时、认证、会话和资源管理，不重新实现 agent loop。
