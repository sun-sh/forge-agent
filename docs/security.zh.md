# Forge Agent 安全边界

Forge Agent 是一个运行在用户本机上的 coding agent。它默认只监听 127.0.0.1，但 Agent、可信扩展、项目验证命令和终端仍然以启动用户的操作系统权限运行。

**项目 Trust、Git worktree 和 Forge 的保护路径都不是操作系统沙箱。** 不可信仓库应使用容器、虚拟机或受限账号运行。

## 保护内容

- Web 网关使用本机访问令牌、HttpOnly cookie、Host/Origin 检查。
- Provider Key 由 Pi 的认证机制保存，不回显到模型配置界面，也不保存到浏览器 localStorage。
- Plan / Ask 模式只允许受限的内置读取、搜索和 Forge 公共网页读取工具。
- 项目验证命令要求项目处于信任状态。
- 验证失败原样返回模型，并受 verifyRetries 限制。
- protect 路径会在执行前后比较内容指纹；保护文件被修改或无法观察时不能成功交付。
- 验证证据绑定当前工作区和配置版本；外部编辑、终端命令、撤销和 proposal 应用会使旧证据失效。
- Git diff 和文件预览使用参数数组、路径检查、大小限制和敏感文件过滤。
- 公共网页工具不使用浏览器 cookie，不执行远程 JavaScript，并拒绝本机/私有 IP 和带凭据 URL。

## 不要误解的边界

- Agent 可以执行 shell；Forge 的命令超时和进程树终止不是 OS 隔离。
- MCP 和可信扩展可能拥有启动用户授予的权限；模式限制不能限制可信扩展内部的任意代码。
- 保护路径阻止错误交付，不阻止模型短暂写入后恢复原状。
- 工作区指纹是有界内容观察，不是原子文件系统快照，也不是环境证明。
- 模型输出、仓库说明、网页内容和工具输出都应视为不可信输入，不能自行授予权限。
- 远程模型会收到任务所需的项目内容；使用第三方 Provider 前应确认数据处理和服务地址。
